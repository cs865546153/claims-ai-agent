# 新场景：多仓库存预警与补货汇总

适用版本：RowFlow DSL 1.0、浏览器导入协议 1.0。此场景独立于订单城市统计，用于“AI 生成 → 导入 → 逐环节解释 → 运行”的课堂演示。

## 1. 给学员的业务背景

库存来自 HTTP，商品单价来自 RPC。仓库需要知道哪些 SKU 低于安全库存、应该补多少件，以及每个仓库大致需要多少采购预算。预算只计算补货数量乘单价，不包含税费或运费。

先筛选 stock < safetyStock，按 sku 内关联商品资料，再计算 replenishQty = safetyStock - stock、estimatedCost = replenishQty × unitPrice。按 warehouse 汇总，统计 skuCount、补货数量与预算；仅保留预算不低于参数 minBudget 的仓库，按预算降序。

运行参数：tenantId 默认为 T001，minBudget 默认为字符串 "0"，使用 decimal 转为数值。源数据保证库存为非负整数、安全库存为非负整数、单价为合法十进制字符串；商品 sku 唯一。缺少商品资料的库存记录按 inner join 丢弃。

## 2. 新接口契约

| 源 | 配置 |
| --- | --- |
| inventory | HTTP GET `https://demo.rowflow.example/api/inventory`，query 仅 tenantId；credentialRef 为 demo-inventory-reader；rowsPath 为 data.items |
| products | RPC registryRef 为 demo-product-rpc，service 为 demo.catalog.ProductService，method 为 listProducts，serviceVersion 为 '1.0'；args 仅 tenantId；rowsPath 为 data.products |

两个接口均为一次性 scan，不分页，不启用重试。地址、凭据引用、RPC 接入均为演示设定；本页数据放在脚本注释的 mocks 中用于离线演示。

## 3. 可直接复制给 AI 的提示词

```text
请结合提供的 RowFlow 语法手册（01～06）、平台用户手册（14）、
脚本导入与可视化约定（15），以及本文（16）的接口与数据，
生成可导入课堂界面的 inventory_replenishment.groovy 完整文件。

业务：多仓库存预警与补货汇总。
1. HTTP inventory 和 RPC products 使用本文接口、字段和完整样例响应。
2. 筛选 stock < safetyStock，按 sku inner join 商品资料。
3. decimal 转换 unitPrice，再计算 replenishQty = safetyStock - stock，
   estimatedCost = replenishQty * unitPrice；保留 warehouse 和 sku。
4. 按 warehouse 分组，统计 skuCount=count()、replenishQty=sum、estimatedCost=sum。
5. minBudget 参数默认字符串 '0'，decimal 转换后筛选汇总预算 >= minBudget。
6. 按 estimatedCost 降序，通过唯一 emit 输出。

脚本要求：
- 一个 pipeline，dslVersion: '1.0'，所有源先声明再引用，不设置未定义的 API。
- tenantId 默认 T001，两个查询仅接收 tenantId，不增加分页、写入或缓存。
- 使用文档 15 的普通注释协议：头部一个 @rowflow-demo JSON 块，
  包含 version、中文 title/description、默认 parameters 和两个源的完整 mocks.response。
- 每个主要处理环节前放 // @step 唯一英文id 中文标题；一个 def 对应一个操作符。
- 包括两个 from、filter、join、withFields、groupBy、aggregate、预算 filter、sorted 和 emit。
- 闭包显式声明参数，字段用 r['field']，不修改输入 Row，不复用流做多个下游。
- 注释只能提供输入和讲解信息，不能写 expectedRows、结果快照、JavaScript 或另一套计算计划。
- 先输出完整 .groovy 文件内容，再在代码块外列出预期结果和各环节行数。
- 自查结果应符合本文的验收值；不要把预期结果写回注释当作执行结果。
```

把 01～06、14～16 作为 AI 的可用资料，或让 AI 能检索这些文档。不要只提供场景名称就要求它猜 API 与响应路径。

## 4. 预期结果与讲解检查点

minBudget=0 时：

```json
[
  {"warehouse":"上海仓","skuCount":2,"replenishQty":7,"estimatedCost":3216.60},
  {"warehouse":"杭州仓","skuCount":2,"replenishQty":10,"estimatedCost":1506.30}
]
```

| 环节 | 数量与检查点 |
| --- | --- |
| inventory from | 7 行 |
| products from | 4 行；join 先读取右流 |
| 库存不足 filter | 4 行；stock=safetyStock 的记录不入选 |
| inner join | 4 行，单价已转换为数值 |
| withFields | 4 行；补货数量分别 7、4、3、3，预算分别 909.30、519.60、2697.00、597.00 |
| groupBy | 2 个分组描述，分别有 2 行输入 |
| aggregate | 2 行；总补货量 17，总预算 4722.90 |
| minBudget filter | 默认 2 行；minBudget=2000 时仅上海仓 |
| sorted / emit | 默认 2 行，上海仓在前 |
| 请求数 | 无重试时 2 次模拟远程请求 |

这些验收值用于独立检查，不是解释器的结果来源。

## 5. 课堂操作

1. 让 AI 根据提示词生成并保存 `.groovy` 文件。
2. 打开 [HTML 界面](rowflow-demo.html)，点击“导入脚本”，选择文件或粘贴完整代码。
3. 查看解析出的图；依次点库存源、filter、join、预算、分组与汇总，切换环节脚本/输入/输出。
4. 点击“运行演示”，再用“单步演示”按依赖顺序回看；核对预算与源调用数。
5. 在“运行参数”中把 minBudget 改成 "2000"，重跑，确认只剩上海仓。
6. 把某个商品单价改成 "bad"，重跑，观察错误定位与没有部分输出；恢复合法值后再次成功。

已准备参考文件：[examples/inventory_replenishment.groovy](examples/inventory_replenishment.groovy)。可先导入它确认课堂流程，再用 AI 新生成的文件重复演示。平台也能解释其他符合 15 中子集的脚本，不按该参考文件的字节内容或文件名匹配结果。
