# 大模型（LLM）内部核心组成

> 
> 说明：这里指**Transformer 架构的自回归大语言模型**，是当前主流大模型底座，分为**模型结构层、训练基础设施、推理运行时**三大部分，常说的 “模型本身” 主要是 Transformer 网络。

## 一、模型主体：Transformer 网络（核心）

### 1. 输入模块

1. **Tokenizer 分词器**
文本 → 词元 (token) ID。不是按字 / 词简单切分，用 BPE/SPM 等算法，把文字转成词典里的整数索引；词典大小一般 32k~128k。
2. **Embedding 嵌入层**
token ID → 高维向量（Embedding Vector，维度常见 512/1024/4096 等）。把离散文字变成连续向量空间。
3. **位置编码 Positional Encoding**
Transformer 本身没有时序概念，必须注入位置信息，区分 “我爱你” 和 “你爱我”。
   - 经典：正弦余弦位置编码
   - 现在主流：**RoPE 旋转位置编码**（Llama、Qwen、GPT 系列）

### 2. 堆叠的 Transformer Block（重复 N 层，大模型几十～上百层）

每一层结构相同，是大模型计算核心，包含两大子模块，外加归一化、残差连接：

```
输入 → 前置归一化Pre-LN → 多头自注意力MHA → 残差相加 → 前置归一化Pre-LN → 前馈网络FFN → 残差相加 → 输出
```

1. **多头自注意力 Multi-Head Attention, MHA**
最核心机制：让每个 token 可以和序列里其他 token 做相关性计算。

> 
> 变体：GQA 分组查询注意力（Llama2/3，平衡速度与效果）、MQA 多查询注意力
   - Q/K/V：Query 查询、Key 键、Value 值，由输入向量线性投影得到
   - 注意力分数：\(Attention(Q,K,V)=softmax(\frac{QK^T}{\sqrt{d_k}})V\)
   - 掩码 Mask：自回归模型用**下三角掩码**，保证生成第 i 个 token 时看不到未来 token
   - 多头：分成多个独立注意力头，并行捕捉不同类型语义关联（语法、指代、逻辑）
2. **FFN Feed-Forward Network 前馈神经网络**
对每个 token 向量独立做非线性变换，**token 之间不交互**。
主流：`Linear → Activation → Linear`
激活函数：SwiGLU（现在大模型标配，替代 GELU/ReLU），中间隐藏层维度通常是 embedding 维度的 2.5~4 倍。
3. **层归一化 LayerNorm**
稳定训练梯度，对向量维度做标准化；现在大多用**Pre-LN**（先归一化再进注意力 / FFN，GPT2、Llama），早期是 Post-LN。
4. **残差连接 Residual Connection**
\(x + SubLayer(x)\)，解决深层网络梯度消失，保证信息可以跨层流通。

### 3. 输出模块

1. **最后的 LayerNorm**：对最后一层 Transformer 输出做归一
2. **LM Head（语言模型头）**：线性层，把向量映射回词表维度，得到每个 token 的 logits 分数
3. **Softmax**：logits 转概率分布，采样下一个 token；训练时用来算交叉熵损失

## 二、模型权重（可学习参数，大模型的 “知识载体”）

所有上面线性层、embedding 层里的矩阵，就是**权重参数**。

- 7B 模型≈70 亿可训练参数；权重以 FP16/BF16/INT4 等格式存储
- 知识不是存在单独数据库，而是**编码在权重矩阵的数值里**，训练通过反向传播不断更新权重。

> 
> 权重分为：Embedding 权重、MHA 的 QKV/O 投影矩阵、FFN 两层线性权重、LMHead 权重。

## 三、训练侧配套组件（训练大模型必备，不属于推理时模型网络本身）

1. **损失函数：交叉熵 Cross Entropy**
预测下一个 token，和真实 token 做损失，反向传播更新权重。
2. **优化器**：AdamW 为主，控制权重更新方向与步长
3. **学习率调度器**：warmup 升温 + cosine 衰减
4. **数据流水线**：文档清洗、去重、过滤、打包成训练样本
5. **分布式训练框架**：Megatron-LM、DeepSpeed、Colossal-AI，做张量并行、流水线并行、数据并行

## 四、推理侧运行组件（模型上线调用）

模型网络本身不变，增加推理优化层：

1. **KV Cache**：推理最关键优化，缓存每一步 K/V 向量，避免每轮生成重复计算历史 token 注意力，大幅提速
2. **采样器**：从概率分布选 token，支持 greedy 贪心、top-p、top-k、temperature 温度控制
3. **量化引擎**：AWQ/GPTQ，把 FP16 权重压缩到 INT4/INT8 降低显存
4. **推理框架**：vLLM、TensorRT-LLM、Text Generation Inference，PagedAttention 分页内存管理

## 五、附加能力模块（基座 LLM 之外，用来对齐）

基座模型预训练完成后，额外叠加：

1. **SFT 有监督微调**：用指令数据微调权重，学会按指令回答
2. **RLHF / DPO 人类偏好对齐**：调整输出风格，减少有害输出，提升有用性；DPO 是 RLHF 替代方案，更简单稳定
3. **RAG 检索增强（不属于模型本身）**：外挂向量库，实时检索外部文档，给模型做上下文补充，**不修改模型权重**

# 极简一句话总结

大模型主体 = **分词器 + Embedding + 多层 Transformer Block（多头自注意力 + FFN+LN + 残差）+ LM Head**；知识保存在网络权重矩阵中，训练靠反向传播更新权重，推理依靠 KV Cache 加速生成。

## 六、两大架构范式：稠密 vs MoE 稀疏（核心基础知识）

> 当前主流大模型按 **FFN 实现方式** 分为两大家族，推理行为、部署成本、训练难度完全不同。

### 核心对比表

| 维度 | **稠密模型** | **稀疏模型 (MoE, Mixture of Experts)** |
|------|--------------|----------------------------------------|
| **代表模型** | GPT-3/4 早期, LLaMA 1/2/3, Qwen 1/2, Mistral, Yi | **DeepSeek-V3, Mixtral 8x7B/8x22B, Nemotron 4, GPT-4(传闻)** |
| **FFN 结构** | 单一大 FFN（所有 token 共用） | **多个专家 FFN + Router 路由** |
| **推理激活参数** | **100%**（总参数 = 激活参数） | **~5%~15%**（仅激活 Top-K 专家） |
| **总参数 vs 激活参数** | 相等 | 总参数 ≫ 激活参数（如 671B 总 / 37B 激活） |
| **显存占用** | 全权重常驻 | **全权重常驻（不省显存，只省算力）** |
| **推理延迟** | 与总参数成正比 | 接近激活参数量级，但有 All-to-All 通信开销 |
| **训练难度** | 相对简单，收敛稳 | 专家负载均衡、路由塌陷、通信开销大 |
| **部署生态** | 成熟，vLLM/TensorRT-LLM 原生支持 | 需专用框架支持 Expert Parallelism |
| **适用场景** | **中小规模、自托管、微调友好、生态最强** | **超大规模旗舰、追求极致算力效率** |

---

> ⚡ **核心区别只在 FFN，不在 Embedding/Attention**
> 
> | 组件 | 稠密 | MoE | 说明 |
> |------|------|-----|------|
> | **Embedding** | 相同 | 相同 | 词表映射、位置编码完全一致 |
> | **Attention** | 相同 | 相同 | 多头自注意力、RoPE、KV Cache 完全一致 |
> | **LayerNorm/Residual** | 相同 | 相同 | 归一化、残差连接完全一致 |
> | **FFN（关键区别）** | 单一大矩阵 | **多专家+Router** | **唯一不同点** |
> | **LM Head** | 相同 | 相同 | 输出投影、Softmax 完全一致 |
> 
> > **一句话**：稠密 vs MoE = **FFN 这一层的实现方式不同**。输入输出流程、Attention 机制、Embedding 全都一样。

---

### MoE 机制速览（以 DeepSeek-V3 为例）

```
每层 FFN 替换为 MoE 层：

输入 → Router (Top-K 选择) → 激活 K 个路由专家 + 共享专家 → 专家并行计算 → 加权求和 → 输出
```

| 指标 | 数值 |
|------|------|
| **总参数** | 671B |
| **路由专家数** | 256 |
| **共享专家** | 1（始终激活，保底能力） |
| **Top-K** | 8 |
| **激活参数/层** | **~37B**（≈ 总参数的 5.5%） |
| **推理算力相当于** | 37B 稠密模型 |

---

### 关键误区澄清

| 误区 | 真相 |
|------|------|
| **MoE 节省显存** | ❌ **不节省**。所有专家权重都要加载到显存/内存，**只是算力省了** |
| **MoE 推理更快** | ✅ 单 Token 前向更快（只算激活参数），但 **Expert 间 All-to-All 通信** 成新瓶颈 |
| **同算力下 MoE 更强** | ✅ 训练同等算力，MoE 通常更强；但同激活参数下，稠密往往更稳、更易收敛 |
| **MoE 难微调** | ✅ 全量微调极难，通常用 LoRA/Adapter 仅调 Router 或部分专家 |

### 行业现状（2024-2025）

| 阵营 | 策略 |
|------|------|
| **闭源旗舰** | GPT-4, Claude 3.5, Gemini —— **MoE 为主**（算力效率至上） |
| **开源主流** | LLaMA-3, Qwen2.5, Mistral, Yi —— **稠密为主**（部署简单、生态友好、微调易） |
| **新兴极致** | DeepSeek-V3, Nemotron 4 —— **万亿总参数、百亿激活参数** 的极致 MoE |
| **混合趋势** | 稠密底座 + 部分 MoE 层、推理时动态路由 |

### 一句话选型建议

| 场景 | 推荐 |
|------|------|
| **个人学习 / 中小企业自托管 / 需频繁微调** | **稠密（LLaMA-3, Qwen2.5, Mistral）** |
| **追求旗舰能力 / 极致性价比推理 / 有专业运维团队** | **MoE (DeepSeek-V3, Mixtral)** |
| **不确定** | **先用稠密**，生态最完善、坑最少 |
