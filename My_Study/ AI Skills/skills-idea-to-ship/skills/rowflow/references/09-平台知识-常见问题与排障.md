# 平台知识：常见问题与排障

适用版本：RowFlow 演示规范 1.0。知识编号：KB-FAQ。各问答只解释本套资料定义的能力，精确规则链接回对应手册。

## FAQ-01：保存成 .groovy 后，为什么不能直接用普通 Groovy 运行？

`pipeline`、`source`、`from` 和 `emit` 是平台注入的 DSL API。普通 Groovy 运行时没有这些入口，需要 RowFlow 宿主。本套资料提供浏览器受限 DSL 解释器用于本地演示，未提供完整 Groovy 宿主或安装命令。见 [脚本入口](01-语法手册-脚本结构与执行入口.md)。

## FAQ-02：为什么 HTTP 已经 200 了还报 RF-SRC-003？

HTTP 状态成功后还要解析 JSON、定位 `rowsPath/recordPath` 并检查类型。`rowsPath: 'data.items'` 对应值为 null、缺失、对象而非数组，或者数组中混入标量，都会失败。检查实际脱敏响应和 [路径规则](02-语法手册-数据源配置.md)。

## FAQ-03：服务直接返回数组，rowsPath 怎么写？

使用 `rowsPath: '$'`。本框架不接受 `$.data.items` 这种 JSONPath 语法；嵌套对象用 `'data.items'`。见 [数据源配置](02-语法手册-数据源配置.md)。

## FAQ-04：map 后为什么找不到 userId 了？

`map` 生成完整新行，不保留未列出的字段。仅补充或覆盖字段时用 `withFields`；使用 `map/select` 时应保留后续 join/lookup 所需的键。见 [单流操作符](04-语法手册-单流操作符.md)。

## FAQ-05：字段缺失会立刻报错吗？

普通读取返回 null，`select` 也会输出 null。`decimal(null)` 或对 null 执行不合法操作才会失败。需要区分缺失与显式 null，用 `r.has('field')`。见 [Row 与表达式](03-语法手册-Row与表达式.md)。

## FAQ-06：为什么输入 false 却变成默认 true？

如果脚本使用了 `value ?: true`，Groovy 会把 false 当作假值。运行参数应使用 `param('enabled', true)`，它只对缺失或 null 使用默认值；Row 字段使用显式 null 判断。见 [参数读取](01-语法手册-脚本结构与执行入口.md) 和 [空值规则](03-语法手册-Row与表达式.md)。

## FAQ-07：两边 userId 都是 null，为什么 join 没有匹配？

这是框架定义的行为。join 不匹配空键，联合键中任一分量为 null 也不匹配。distinct/groupBy 则把相同空键视为同键。见 [Row 键规则](03-语法手册-Row与表达式.md)。

## FAQ-08：left join 为什么让一条订单变成三条？

右表该键有三条匹配记录，框架会调用合并闭包三次。检查右表是否应当唯一、键是否遗漏 tenantId 等维度。只有业务明确允许时，才能对右表先 distinct；默认保留第一条不等于选择了正确资料。见 [关联语义](05-语法手册-多源组合与聚合.md)。

## FAQ-09：需要保留没有用户资料的订单，用什么？

可以使用 `join(..., [type: 'left', ...])`，或 `lookup(..., [mode: 'left', ...])`。合并闭包中处理第二个参数为 null 的情况。正常未命中和远程错误不同；如要对调用错误降级，须另行明确 `onError: 'null'`。见 [多源组合](05-语法手册-多源组合与聚合.md)。

## FAQ-10：为什么 RPC timeoutMs 是 800，任务却超过 800ms 才结束？

800ms 是一次调用尝试的上限。多行 lookup、重试及等待会累计耗时，整个任务还受 pipeline.timeoutMs 约束。`retries: 1` 表示最多两次调用，不是一次。见 [时限与重试](06-语法手册-执行限制与错误处理.md)。

## FAQ-11：设置 onError: 'null' 后，为什么权限和响应路径错误仍使任务失败？

该配置只用于 lookup 的 `RF-SRC-001/002`。平台权限错误 `RF-PERM-001` 和响应结构错误 `RF-SRC-003` 等不能降级；否则错误接入可能伪装成“没有数据”。scan 没有此选项。见 [错误处理](06-语法手册-执行限制与错误处理.md)。

## FAQ-12：同一个用户出现两次，lookup 会复用第一次结果吗？

不会。1.0 无缓存、批量查询或自动去重。每个输入行分别查询，重试也计入请求额度。不要为了省查询而对订单按 userId 去重，除非业务允许丢弃其他订单。见 [接入与性能](08-平台知识-接入权限与性能.md)。

## FAQ-13：sum 为什么不能直接统计字符串金额？

sum 只接受 Number 或 null，字符串先用 `decimal` 转换。需要忽略空金额时用 `r['amount'] == null ? null : decimal(r['amount'])`。`decimal(null)` 本身会失败。见 [聚合指标](05-语法手册-多源组合与聚合.md)。

## FAQ-14：空输入时，为什么有时返回 []，有时返回一条统计记录？

分组聚合没有分组可输出，结果为 `[]`。全局 aggregate 始终输出一行，其中 count 为 0、sum 为 0、avg/min/max 为 null。见 [全局聚合](05-语法手册-多源组合与聚合.md)。

## FAQ-15：给 limit(10) 后为什么仍然拉取了整个 HTTP 响应？

limit 截取的是框架中的流，不是接口的远程分页。HTTP scan 本来就一次获取响应；sorted、groupBy 或 join 右流也可能已经读完上游。1.0 不会自动请求 page/pageSize 或循环游标。见 [执行模型](06-语法手册-执行限制与错误处理.md)。

## FAQ-16：maxOutputRows 是不是自动取前 N 条？

不是。超过上限时整个任务失败；需要截取时写 limit，并检查是否会改变聚合或排序含义。超限不是正常的空结果，也不会返回可用的部分结果。见 [任务限制](06-语法手册-执行限制与错误处理.md)。

## FAQ-17：为什么复用同一个流变量会报 RF-DSL-003？

同一个节点不允许有多个下游消费者。分别从同一个源调用两次 from 可以产生两个独立流，但会读取两次且没有统一快照。1.0 不提供 cache、fork 或 broadcast。见 [脚本结构](01-语法手册-脚本结构与执行入口.md)。

## FAQ-18：union 会自动去重或对齐字段吗？

都不会。union 先输出左流再输出右流；去重使用 distinct，字段对齐使用 map/select。两侧同名字段含义也需要由服务契约保证。见 [union](05-语法手册-多源组合与聚合.md)。

## FAQ-19：能写 collect、parallel 或 SQL 吗？

RowStream 1.0 没有这些 API。结果输出用 emit，统计用 aggregate；并行或 SQL 需求超出当前规范。当前行内部的 List 可以用 collect 生成新的 List，这不代表 RowStream 也支持 collect。见 [脚本边界](01-语法手册-脚本结构与执行入口.md)。

## FAQ-20：需要 JDBC、自动分页、缓存或定时执行怎么办？

本规范未定义这些能力，也没有可用的配置键。应补充需求并扩展规范、平台接入或运行时。知识答疑要明确边界；代码生成不能添加猜测的 API。见 [平台边界](07-平台知识-架构与运行流程.md)。

## FAQ-21：报错排查顺序是什么？

先确认错误码和操作符位置，再检查引用与配置、接入权限、服务响应结构、字段类型、业务关联关系，最后结合调用数和耗时检查限制。不要先把所有 timeout 和 maxRows 都调到最大。错误码清单见 [错误处理](06-语法手册-执行限制与错误处理.md)。

## FAQ-22：示例里的服务和凭据可以直接使用吗？

不可以。`.example` 地址、RPC 服务、注册配置和凭据引用均为演示设定，需要接入平台真实配置或 mock。文档示例的预期结果按固定样例计算，不代表已经连通任何服务。见 [示例契约](10-示例数据与服务契约.md)。

## FAQ-23：导入的脚本必须和内置示例完全一样吗？

不需要。通过“导入脚本”选择文件或粘贴内容后，界面解析实际变量和操作符依赖，并根据脚本计算结果。支持范围见 [15 导入约定](15-脚本导入与可视化约定.md)。没有节点注释也会生成图；新远程接口需提供本地样例响应。

## FAQ-24：注释里的数据流和输出能代替真实脚本吗？

不能。@step 只命名节点，@rowflow-demo 只提供元信息、默认参数和输入响应。界面从真实代码构建图并执行受限 DSL；不读取注释中的预设结果。修改脚本后会隐藏旧快照，需要重新解析；详见 [15](15-脚本导入与可视化约定.md) 和 [平台用户手册](14-平台界面讲解指南.md)。
