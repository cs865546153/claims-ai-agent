# 手动测试材料

这些 `.txt` 文件用于在前端工作台（http://127.0.0.1:8001/）手动测试「我要申请理赔 → 材料审核」链路。

## 材料清单与对应检查项

材料完整性检查（`tools/material_check.py`）按**文件名 / 识别出的单证类型**是否含关键词判断：

| 文件 | 覆盖检查项 | 触发关键词 |
|---|---|---|
| `01_机动车保险保单.txt` | 保单信息 | 保单 / 保险凭证 |
| `02_交通事故认定书.txt` | 事故或出险证明 | 事故 / 出险 / 报案 / 交警 / 病历 等 |
| `03_车辆维修报价单.txt` | 费用或损失凭证 | 发票 / 维修报价 / 定损 / 费用清单 等 |

> 文件名已含关键词，即使单证识别模型的 `document_type` 不精确也能通过材料检查。

## 测试步骤

### 场景 A：理赔报案 + 材料审核（主流程）

1. 打开 `http://127.0.0.1:8001/`（首次请 **Ctrl+F5** 硬刷新）
2. 点顶栏下方快捷按钮「**我要申请理赔**」
   - 预期：识别为「理赔报案」，回复「第 1 轮材料核查仍缺少：保单信息、事故或出险证明、费用或损失凭证。请继续上传…」
3. 点输入框左侧「**＋**」上传按钮，选中上面 3 个文件，再发送（输入「已上传材料」或直接发送）
   - 预期：材料齐全，回复客服预审结果

**分步观察追问（可选）**：每次只上传 1 个文件并发送「继续」，可看到每轮追问逐项减少。

### 场景 B：保单查询

输入「查询保单 POL-2024-001」，预期返回保单摘要（有效 / 保额 / 来源标注模拟数据）。

### 场景 C：正式核赔 + RAG 判责

点顶栏「**真实理赔演示**」按钮，预期右侧链路面板三专家节点显示「引用条款 clause-xxx」。
