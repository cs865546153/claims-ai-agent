# 平台知识：接入权限与性能

适用版本：RowFlow 演示规范 1.0。知识编号：KB-OPS。本文面向准备接口、诊断权限和优化处理链的用户。

## 1. 接入前准备什么

HTTP 接入需要固定 HTTPS URL、请求方式、静态请求参数、JSON 响应样例、结果路径及项目可用的 `credentialRef`。RPC 接入需要 `registryRef`、服务名、方法名、服务版本、Map 参数和响应样例。

平台服务目录记录：允许访问的目标、方法、项目、凭据绑定、幂等属性和适配器。目录由平台管理者维护；脚本只引用已授权条目。

具体脚本配置字段见 [数据源手册](02-语法手册-数据源配置.md)。没有列在手册里的接入选项不能由 AI 自行添加。

## 2. 凭据引用如何工作

`credentialRef` 是逻辑标识，不是 Token 本身。平台在调用前解析当前项目的凭据并注入认证信息；脚本及任务输出不应包含密钥。

同一个名字在不同项目下不保证指向相同凭据，跨项目复制脚本后仍需重新确认授权。凭据不存在、未授权、目标域名不在白名单、RPC 方法未授权，都报 `RF-PERM-001`。

服务返回 HTTP 401/403 时属于远程调用失败 `RF-SRC-002`；平台在调用前发现自身授权缺失才是 `RF-PERM-001`。前者可以在 lookup 显式降级配置下转换为空结果，后者必须失败。两种情况都需要检查授权，不能仅靠错误码猜测为“用户不存在”。

脚本的普通 `headers` 不接受 `Authorization`、`Cookie`、`Host`；含这些字段时报 `RF-PERM-001`。远程源不需要认证时可以省略凭据引用，但目标仍需授权。

## 3. 重试与幂等

“超时”只代表调用者未及时得到响应，不能据此断定服务端没有执行。即使脚本写了 `idempotent: true`，平台仍检查接入目录，避免重复执行非幂等业务。

1.0 仅覆盖查询型接入。新增订单、扣款、发送通知等写入接口不在本规范中。重试是同一次任务内对单次远程读取的有限恢复，不是业务补偿，也不是整个脚本重跑。

精确的重试状态码和降级范围见 [错误处理](06-语法手册-执行限制与错误处理.md)。

## 4. 性能问题先看哪里

| 现象 | 常见原因 | 建议 |
| --- | --- | --- |
| lookup 请求数接近输入行数 | 每行串行查询，重复 ID 也会再次查 | 先做业务筛选；若可获取完整小维表，考虑 join |
| 关联后行数突然增加 | 右表同键有多条，一对多展开 | 检查键及维表契约；只有业务允许时才先去重 |
| limit 后仍然很慢 | 上游排序、分组或右表预加载已发生 | 在语义允许处提前筛选，缩小源查询范围 |
| 输出很少但输入超限 | maxRows 约束每个节点，不只最终结果 | 在服务端提供业务过滤参数，避免全量拉取 |
| RPC 多次重试后任务超时 | 每次等待与请求消耗总预算 | 减少调用链长度，核对服务延迟，再调整合法时限 |
| 处理大字段时仍占较多内存 | 行数限制无法描述单行大小 | 缩小服务响应字段与范围，关注 2 MiB 响应上限 |

平台不会自动把本地 `filter` 下推到 HTTP/RPC。若接口支持 `tenantId`、状态或时间范围参数，需要显式配置，而且必须在服务契约中确实存在。

## 5. join 的内存与 lookup 的延迟

join 的右侧完整保存在索引中，适合小维表。右表可以是经过 `filter/select` 的处理链；只投影合并需要的字段可减小保存的数据，但不能减少源已经返回的响应体。

lookup 的粗略耗时可按“实际请求次数 × 平均单次延迟 + 重试等待 + 本地处理”估算。例如 100 行、每行约 40ms，在无重试的理想条件下已经约 4 秒。这个估算不是时限承诺；连接开销、尾延迟和任务预算也会影响结果。

不能通过添加未定义的 `parallel`、`maxConcurrency`、`cacheTtl`、`batchSize` 配置解决问题。需要这些能力时先扩展平台规范与实现。

## 6. 不要随意提前去重

订单表中两个订单可能属于同一用户。如果在 lookup 前按 `userId` 去重，会减少请求，也会丢失合法订单。只在业务本来就要求“每位用户一条”时这样做。

若需要保留所有订单且用户资料能一次性获取，使用右表 join 更合适。1.0 没有可复用缓存节点，因此不提供“先查唯一用户、缓存后回填原订单”的内置写法。

## 7. 日志与诊断

优先查看 `runId` 对应的错误码、源名、操作符位置、请求次数和耗时。正常未命中看 `lookupMissRows`，失败后降级看 `lookupErrorFallbackRows`，两者含义不同。

日志不记录凭据值、受保护请求头或完整业务响应。需要对比字段时，使用获准的脱敏样例。排障答疑应引用配置与字段结构，不索取真实 Token。

## 8. 从演示迁移到实际平台

1. 用实际平台已授权的源替换 `.example` 地址和示例引用。
2. 核对服务请求与响应契约，尤其是 scan 数组和 lookup 单对象的差别。
3. 使用明确、脱敏的输入样例验证字段类型和空值。
4. 核对结果行数、金额、排序、一对多及空键行为，再判断任务限制是否足够。
