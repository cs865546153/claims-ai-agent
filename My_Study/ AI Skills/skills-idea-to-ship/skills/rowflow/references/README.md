# RowFlow：脚本生成与平台答疑演示资料

这是一套为 AI 演示构造的框架文档，版本为 **RowFlow 演示规范 1.0**。框架使用 Groovy 风格 DSL，以接近 Java Stream 的方式处理 HTTP、RPC 和内存数据；操作符之间通过底层为 Map 的 Row 传递记录。

配套界面：[打开 RowFlow HTML 演示](rowflow-demo.html)，可离线展示数据源、脚本、Row 变化、模拟结果与内嵌知识库。讲解顺序和操作说明见 [平台界面讲解指南](14-平台界面讲解指南.md)。

本目录交付语法规范、平台知识、示例，以及支持脚本导入的浏览器受限 DSL 解释器。没有完整 Groovy 宿主或已部署服务；业务脚本扩展名为 `.groovy`，本地可按 15 的子集与样例解释演示，生产执行仍需实际平台宿主。文中的 API、错误码和默认限制是本套演示的约定，不属于 Groovy 或 Java 自带功能。

## 两条使用路径

**生成脚本**：先读 01，按需求查 02～06，使用 10 确认字段和远程契约，再参考 11。输出一个完整 `.groovy` 文件，包含数据源声明、处理链和恰好一次 emit。可直接使用 12 中的提示词及演示需求。

**平台答疑**：先检索 07～09；涉及签名、默认值、空值、错误码时回查 01～06；涉及示例数据时查 10。回答中指出依据的文档和章节，资料没有定义的能力应明确说明。

## 最短概念链

`source 注册配置 → from 创建扫描流 → 操作符转换/组合 Row → emit 提交结果`

查询型源通过 `lookup` 接入已有流；另一个扫描流通过 `join/union` 组合。Row 使用 `r['field']` 取值，转换闭包返回新的 Map/Row。`map` 输出完整新行，`withFields` 保留原行并覆盖指定字段。

## 资料的权威范围

- **语法与行为**：01～06 为规范来源。某个参数的完整默认值只在所属手册维护。
- **平台解释**：07～09 解释规范及常见取舍，不新增接口。
- **业务契约**：10 统一定义远程示例的请求、字段和固定数据。
- **用法与验收**：11～12 展示组合方式；14 定义界面操作，15 定义浏览器导入协议与执行边界，16 定义库存新场景契约和验收值。

若资料出现矛盾，优先按对应语法手册及服务契约判断，并先修正文档；不要让 AI 靠猜测选择一种行为。新增操作符或数据源时，应同步更新所属手册、完整示例和验收案例。

## 演示边界

1.0 面向有界、查询型、小规模数据编排，不定义自动分页、SQL、缓存、并发、JDBC、实时流、调度或跨源事务。示例域名 `.example`、RPC 服务和凭据引用为占位设定。

Groovy 语法及 Stream 设计的外部参考链接放在 [01 的语言设计参考](01-语法手册-脚本结构与执行入口.md)。自定义 RowFlow 行为以本目录文档为准。预期结果来自固定样例计算，不代表已在真实 RowFlow 运行时执行。

## 导入新场景

使用 [16 中的提示词](16-新场景-库存补货演示与AI提示词.md) 让 AI 生成脚本，再导入 HTML 界面。可以先用 [库存补货参考脚本](examples/inventory_replenishment.groovy) 验证流程。节点注释不是执行计划；图和每步数据由实际脚本解析计算。

维护本地界面源代码或 Markdown 后，运行 `python3 tools/build_demo.py` 同步成单个离线 HTML。终端构建仅供维护，打开 HTML 不需要安装依赖。
