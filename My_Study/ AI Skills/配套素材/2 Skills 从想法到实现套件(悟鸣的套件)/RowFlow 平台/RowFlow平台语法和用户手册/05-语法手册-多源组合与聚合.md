# 语法手册：多源组合与聚合

适用版本：RowFlow 演示规范 1.0。`join` 与 `union` 接受另一个 RowStream；`lookup` 直接引用查询型数据源。分组只创建分组描述，必须接 `aggregate` 才能得到可输出的流。

## 1. join：关联两个扫描流

签名：`left.join(RowStream right, Map options, Closure merger) -> RowStream`。

```groovy
def result = from('orders').join(from('users'), [
    type: 'left',
    leftKey: { l -> l['userId'] },
    rightKey: { r -> r['userId'] }
]) { l, r ->
    [
        orderId: l['orderId'],
        userId: l['userId'],
        city: r == null ? '未知' : r['city'],
        amount: l['amount']
    ]
}
```

| 选项 | 规则 |
| --- | --- |
| `type` | 默认 `'inner'`；支持 `'inner'`、`'left'` |
| `leftKey` | 必填；`左 Row -> key` |
| `rightKey` | 必填；`右 Row -> key` |

框架完整读取右流并建立索引，然后按左流顺序处理。`inner` 只输出匹配记录；`left` 对未匹配左行调用一次合并闭包，右参数为 `null`。右边同键有 N 条记录时，同一左行产生 N 行，按右边原顺序依次输出。

合并闭包必须返回 Map/Row，并显式决定输出字段；平台不自动拼接两边字段，也没有自动添加前缀或覆盖同名字段的行为。键为 `null` 或联合键包含 `null` 时不匹配，详见 [Row 键规则](03-语法手册-Row与表达式.md)。

右流为空时，`inner` 输出零行，`left` 保留每一条左行并传入空右参数。1.0 不支持 `right`、`full`、交叉关联或自定义任意谓词关联。

## 2. lookup：根据当前行查询一个对象

签名：`stream.lookup(String sourceName, Map options, Closure merger) -> RowStream`。

```groovy
def result = from('orders')
    .filter { r -> r['userId'] != null }
    .lookup('userById', [
        request: { r -> [userId: r['userId']] },
        mode: 'left',
        onError: 'fail'
    ]) { order, user ->
        [
            orderId: order['orderId'],
            userId: order['userId'],
            city: user == null ? '未知' : user['city']
        ]
    }
```

`userById` 必须为 `mode: 'lookup'` 的 HTTP/RPC 数据源。

| 选项 | 默认值 | 规则 |
| --- | --- | --- |
| `request` | 无 | 必填；`输入 Row -> Map`，动态业务请求参数 |
| `mode` | `'left'` | `'left'` 保留未查到的行；`'inner'` 丢弃未查到的行 |
| `onError` | `'fail'` | `'fail'` 使任务失败；`'null'` 对允许降级的远程错误按未查到处理 |

动态参数如何合并见 [数据源配置](02-语法手册-数据源配置.md)。合并闭包的第二个参数为 Row 或 `null`；返回值必须为 Map/Row。

1.0 逐行串行调用 lookup，每个输入行最多得到一个对象，不提供批量、并行、缓存或同键自动去重。两行相同 `userId` 仍产生两次逻辑查询。初次调用与重试均计入 `maxLookupCalls`。

成功返回显式 `null` 是正常未命中。远程失败是错误，只有 `onError: 'null'` 且错误属于允许降级类别时才转换为空结果。`mode: 'inner'` 配合降级会丢行，需由需求明确允许。降级范围见 [错误处理](06-语法手册-执行限制与错误处理.md)。

## 3. join 和 lookup 如何选择

| 情况 | 使用方式 | 调用和内存特点 |
| --- | --- | --- |
| 可以一次获取完整的小型用户维表 | `join(from('users'), ...)` | 完整读取右表一次并建立索引 |
| 服务只支持按用户 ID 查询 | `lookup('userById', ...)` | 每行调用一次，可配置有限重试 |
| 需要一个键对应多条右记录 | `join` | 同键多条会扩大结果行数 |
| 右服务返回单个对象 | `lookup` | 每行最多一条，未命中依 mode 处理 |

## 4. union：顺序拼接两个流

```groovy
def result = from('webOrders')
    .union(from('storeOrders'))
    .distinct { r -> r['orderId'] }
```

签名：`stream.union(RowStream right) -> RowStream`。

先输出左流全部行，再读取并输出右流。`union` 保留重复记录，不检查两侧字段集合相同，也不补齐字段；需要统一结构时先分别 `map/select`。去重必须另接 `distinct`。

不能把同一个流对象传给自己的 `union` 或在两条支路中共用。独立的两次 `from` 可以拼接，但会分别读取来源。

## 5. groupBy 与 aggregate

```groovy
def result = from('orders')
    .groupBy([city: { r -> r['city'] }])
    .aggregate([
        orderCount: count(),
        totalAmount: sum { r -> decimal(r['amount']) },
        averageAmount: avg { r -> decimal(r['amount']) },
        minAmount: min { r -> decimal(r['amount']) },
        maxAmount: max { r -> decimal(r['amount']) }
    ])
```

`groupBy(Map<String,Closure> keys) -> GroupedRows`，Map 至少一个元素；键是输出字段名，闭包从每条输入行计算分组值。组合分组写成：

```groovy
.groupBy([
    city: { r -> r['city'] },
    channel: { r -> r['channel'] }
])
```

`GroupedRows.aggregate(Map<String,Metric> metrics) -> RowStream`。每个输出 Row 包含分组字段及指标字段；指标 Map 至少一个元素，指标别名不能与分组字段重名。聚合表达式读取原始输入行，不读取同一轮刚计算的其他指标。

分组结果按分组首次出现顺序输出；组内输入顺序不改变。空输入产生零个分组。分组键允许 `null`；所有键相同的空值行进入同组。

## 6. 聚合指标

这些构造器只在 `aggregate` 的配置 Map 中使用，不是 RowStream 的终结方法。

| 指标 | 输入要求 | 空值行为 | 结果类型 |
| --- | --- | --- | --- |
| `count()` | 无闭包，统计输入行数 | 包括字段为 null 的行 | Long |
| `countNonNull { r -> value }` | 任意合法字段值 | 忽略 null | Long |
| `sum { r -> value }` | Number 或 null | 忽略 null；没有有效值时为 `0.0G` | BigDecimal |
| `avg { r -> value }` | Number 或 null | 忽略 null；没有有效值时为 null | BigDecimal 或 null |
| `min { r -> value }` | Number 或 null | 忽略 null；没有有效值时为 null | BigDecimal 或 null |
| `max { r -> value }` | Number 或 null | 忽略 null；没有有效值时为 null | BigDecimal 或 null |

`avg` 以有效值数量为分母，结果保留 2 位小数，采用 HALF_UP 舍入。这是演示规范的固定规则。字符串金额先用 `decimal` 转换；`sum { r -> r['amount'] }` 不能直接消费字符串。

需要忽略空金额时：

```groovy
totalAmount: sum { r -> r['amount'] == null ? null : decimal(r['amount']) }
```

不要写 `decimal(null)`，因为转换会在聚合忽略空值之前失败。

## 7. 全局聚合

`RowStream.aggregate(Map<String,Metric> metrics) -> RowStream` 可直接统计全流：

```groovy
def result = from('orders').aggregate([
    orderCount: count(),
    totalAmount: sum { r -> decimal(r['amount']) }
])
```

全局聚合始终产生一行。空输入时 `count=0`、`countNonNull=0`、`sum=0`、`avg/min/max=null`。这与分组聚合的空输入输出零行不同。

## 8. 聚合后筛选和再计算

```groovy
.groupBy([city: { r -> r['city'] }])
.aggregate([
    orderCount: count(),
    totalAmount: sum { r -> decimal(r['amount']) }
])
.filter { r -> r['totalAmount'] >= 100.00G }
.sorted([direction: 'desc']) { r -> r['totalAmount'] }
```

聚合后得到普通 RowStream，可以继续筛选、映射、排序和输出。SQL 中的 HAVING 在此用聚合后的 `filter` 表达；1.0 没有独立的 `having` 操作符。
