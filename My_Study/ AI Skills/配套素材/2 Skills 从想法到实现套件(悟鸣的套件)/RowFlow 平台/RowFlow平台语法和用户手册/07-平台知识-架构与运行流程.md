# 平台知识：架构与运行流程

适用版本：RowFlow 演示规范 1.0。知识编号：KB-CORE。本文解释框架概念及预期的平台运行方式；方法签名以语法手册为准。

本套资料包含 HTML 课堂界面与浏览器受限 DSL 解释器，没有完整 Groovy 宿主或已部署服务。下述组件与流程定义目标平台；本地解释器的支持范围和差异见 [脚本导入与可视化约定](15-脚本导入与可视化约定.md)。

## 1. 平台解决什么问题

把多个查询型数据源转成统一的 Row 流，用接近 Java Stream 的链式操作组合、清洗、关联和聚合，最后得到 JSON 数组。用户描述处理逻辑，平台负责已授权的数据访问、执行限制和运行诊断。

典型任务：读取 HTTP 订单列表，关联 RPC 用户资料，按城市统计已支付金额。它面向有限规模的数据编排，不承担长期运行的实时流、离线海量计算或跨服务写入事务。

## 2. 核心对象

| 对象 | 含义 | 常见误解 |
| --- | --- | --- |
| Pipeline | 一个脚本的一次执行计划 | 不等于持续运行的服务 |
| Source | 一份命名的数据源配置 | 注册不代表立刻请求 |
| Row | 单条只读记录，底层是 Map | 不是数据库固定 schema 的表行 |
| RowStream | 传递 Row 的惰性处理链 | 不是 Groovy List，也不是标准 Java Stream |
| Operator | 筛选、映射、关联等节点 | 闭包里不能自行发网络请求 |
| GroupedRows | 分组描述 | 必须 aggregate 后才能继续普通流操作 |
| Metric | 聚合指标描述 | count/sum 等构造器不是终结操作 |
| Emit | 唯一输出入口 | 不允许每处理一行调用一次 |
| Connector | HTTP/RPC 等接入适配层 | 认证和服务发现不由业务脚本实现 |

## 3. 从脚本到结果的处理路径

1. **接收脚本与参数**：以 `.groovy` 文本、DSL 版本和 JSON 参数形成任务输入。
2. **解析与校验**：检查语法子集、API 和配置键白名单、必填参数、源引用及流的消费关系。
3. **接入授权**：核对域名、凭据引用、RPC 注册配置、服务与方法权限。
4. **生成执行计划**：将 from、filter、join 等调用连接为有向处理图，一个流节点仅允许一个下游。
5. **拉取与执行**：HTTP/RPC 返回值转换成 Row，闭包按定义逐行或聚合执行。
6. **提交结果和记录诊断**：成功提交完整 JSON 数组；失败只提交错误详情及诊断指标。

Row 的 schema 是动态的：平台能提前检查配置结构，不能凭脚本推断远程响应所有字段一定存在。`r['missing']` 返回 null，后续转换或计算可能因此报错。

## 4. 平台操作的语义

演示平台区分三类动作，不预设具体控制台按钮或命令行名称：

| 动作 | 做什么 | 是否读取业务远程数据 |
| --- | --- | --- |
| 静态校验 | 解析、配置、参数、引用、图结构与接入权限检查 | 否 |
| 预览 | 执行当前脚本，展示结果和诊断 | 是 |
| 正式运行 | 用指定脚本版本和参数执行并保存任务记录 | 是 |

预览与正式运行使用相同处理语义。预览需要真实的接入权限和服务可用性；不能把预览当成零调用的模拟。若没有服务，可将源替换为 `memory` 做本地数据演示，但仍需要 RowFlow 宿主才能实际执行 DSL。

## 5. 任务状态

预期状态流转为：`QUEUED → VALIDATING → RUNNING → SUCCEEDED/FAILED`。在 `VALIDATING` 失败时直接进入 `FAILED`，不会读取业务源；运行期间失败也进入 `FAILED`，已发生的请求不会回滚。

任务运行记录关联 `runId`、脚本版本、参数摘要、输出行数、各源请求次数、耗时及错误位置。输出与运行元数据分开保存；业务流里没有自动添加的 `runId` 字段。

## 6. 顺序和一致性

- memory 按 `rows` 列表顺序；HTTP/RPC scan 按响应数组顺序。
- 平台不保证远程接口两次返回相同顺序或数据快照。
- lookup 保持输入顺序；join 保持左流顺序及同键右记录顺序。
- groupBy 按分组首次出现顺序；sorted 可显式建立业务排序。
- 不同数据源之间没有统一快照或分布式事务。先读订单再读用户，两个服务的数据可能在读取间发生变化。

需要稳定的展示顺序时写出 `sorted`。需要业务快照一致性时，须由上游接口提供共同版本或快照契约，本规范没有自动实现。

## 7. 惰性执行不等于无限流

“惰性”表示未连接到输出的链不读取、逐行节点按需取数。HTTP scan 仍需要收到并解析完整响应；排序、分组、右表关联等也需要保存数据或状态。因此本平台限定有界输入，并通过行数、请求数、响应大小和总时限保护执行。

例如 `from('orders').sorted { ... }.limit(10)` 先读取全部订单再排序。把 `limit` 放到后面不会缩小右表关联索引，也不会替上游服务实现分页。

## 8. 脚本版本与规范版本

`dslVersion: '1.0'` 决定 DSL 的语法与行为。脚本版本用于平台记录某次业务逻辑文本。RPC `serviceVersion` 则指远程业务服务版本，三者不能混用。

升级 DSL 应先修改手册、示例和验收案例，再升级运行时。知识答疑遇到当前版本未定义的能力，应说明边界，而不是推测另一个版本存在。

## 9. 平台没有定义的部分

本规范不定义安装包、SDK 依赖坐标、真实控制台地址、CLI、定时调度、持久化结果表、缓存、并行度、组织审批或生产部署方式。回答这些问题时，应明确资料不足；不能把本资料中的设计写成已经上线的产品事实。

## 10. 导入脚本如何展示数据流

HTML 界面从脚本的变量和操作符依赖构建图，使用本地样例解释计算每个节点的输入、输出和失败位置。@step 仅提供讲解标签，@rowflow-demo 仅提供元信息、默认参数和样例响应；不会执行注释中的另一套图或读取预设结果。

导入不要求与内置模板相同。修改代码或运行参数后必须重新解析，旧图和快照应隐藏；某个环节失败时最终没有业务结果。导入、完整脚本导出及单步演示操作见 [平台用户手册](14-平台界面讲解指南.md)。
