# 业务任务经验卡（简版）

**任务名称：**医疗理赔材料预审与处理建议


## 1. 场景

客户提交了医疗收费票据、门诊病历和费用清单。理赔人员需要先看懂这次就诊，判断材料能否关联、费用是否一致、还有什么问题影响后续审核，并明确下一步先核实什么、是否需要补充材料。

希望把这套预审方法沉淀下来，让 AI 能够说明“依据是什么、问题在哪里、接下来怎么办”，帮助人工减少重复整理和无针对性的补件。

本轮只做就医材料整理、关联与费用核对、证据缺口分析、核实及补件建议。不作保险责任认定、用药合理性认定、单证真伪认定或赔款计算。

## 2. 输入

**创建 Skill 时提供：**

- 本经验卡：处理顺序、判断规则、人工确认点和异常处理要求。
- 两组教学样例及本卡中的预期结果，用于演示和回归验证。两组是同一就诊的正常样例与金额冲突对照样例，分别运行，不合并为同一批次。
- 后续由业务专家补充或修订的规则，需注明来源、适用范围、版本、例外和对应验证样例。

**每次使用时提供：**

- 一个明确的待处理材料目录，内含获准处理的照片或 PDF；本次课堂使用合成材料。
- 如有：本次要解决的具体审核问题，以及经过确认的补充说明或更正记录。没有则写“未提供”。

**当前样例文件：**

| 样例 | 原始材料 | 使用目的 |
| --- | --- | --- |
| 第一份独立材料 | `01_医疗收费票据.jpg`、`02_门诊病历.pdf`、`03_费用清单.png` | 验证材料关联、费用一致，以及不误报正常单一来源 |
| 第二份独立材料 | `01_医疗收费票据.jpg`、`02_门诊病历.pdf`、`替换用_费用清单.pdf` | 验证跨材料金额差异定位及后续核实建议 |

读取时以原始单证为证据。目录中的历史 JSON、OCR 文本和旧报告仅作辅助，不能替代原件；本卡的预期结果不能直接复制为新批次事实。运行输入、生成结果和验收参考分别识别。

## 3. 输出

### 3.1 给理赔人员看的预审意见单

生成 `材料预审意见单.pdf`，按同次就诊分组，包含：

1. **就诊摘要：** 患者、医院、院内患者号、就诊号、就诊日期、病历记载的诊断及其限定。
2. **材料关联结论：** 哪些材料可以关联，依据是什么；哪些关系仍待核实。
3. **费用核对表：** 单据内部合计、跨单据总额、费用类别、支付构成及计算结果。
4. **问题与处理建议：** 每项写清“事实和来源 → 对应规则 → 判断及影响 → 证据缺口 → 下一步”。按处理顺序排列，并区分已经发现的问题与满足条件时才需要开展的进一步核实。
5. **预审总评：** 用“当前核对范围内未见矛盾”“待核实材料关联”“待核实费用差异”等具体表述；未评估的事项单独说明，不写成“审核通过”或“材料全部齐全”。

来源至少定位到文件名、页码及对应字段或表格行。照片按第1页记录，不能编造无法取得的坐标。

### 3.2 供系统继续使用的结构化结果

生成 `材料预审结果.json`，承载与意见单一致的内容：材料清单、就诊分组、原始值及来源、标准化值、计算过程、规则编号、核对结果、待核实项和建议动作。

原始值与归并结果分别保存；发生冲突时保留各方值，不用一个值覆盖另一个值。字段缺失使用空值并注明原因，不用0代替未知金额。金额使用十进制定点计算或整数分计算，输出统一为元、保留两位小数。

### 3.3 当前样例的验收参考

**第一组：**

- 三份材料中的患者、医院、院内患者号、就诊号和就诊日期一致，支持按同次就诊归集；这不等于已核实真实身份或同一保险事故。
- 清单：25.00 + 60.00 + 20.00 + 136.40 = **241.40元**。
- 类别核对：诊察费25.00元；检验费60.00 + 20.00 = 80.00元；药品费136.40元，与票据对应类别一致。
- 支付构成：160.00 + 81.40 = 241.40元，算术自洽；**不能输出“应赔81.40元”**。
- 诊断只见于病历、医保支付只见于票据，不因来源数量少自动列为异常或补件项。
- 保留“初步诊断：急性上呼吸道感染”“自述无特殊病史”；未附检查结果、具体药名不足以支持进一步专业判断，按具体审核需要提出条件性建议，不一律要求补齐。

**第二组：**

| 费用类别 | 票据金额（元） | 清单对应金额（元） | 清单减票据（元） |
| --- | ---: | ---: | ---: |
| 诊察费 | 25.00 | 25.00 | 0.00 |
| 检验费 | 80.00 | 80.00 | 0.00 |
| 药品费 | 136.40 | 156.40 | 20.00 |
| 合计 | 241.40 | 261.40 | 20.00 |

必须指出：两份单据各自内部加总正确，**跨材料差额20.00元全部来自药品费**。建议先核对原始收费记录及对应版本，确认补收、退费或更正情况；差异解决前保留两套金额，费用金额待核实。

可参考这样的意见：

> 三份材料的就诊关联信息一致。票据药品费136.40元、清单药品费156.40元，差额20.00元，构成全部总额差异。建议先核对对应收费记录及材料版本，确认是否发生补收、退费或更正；必要时取得相互对应的材料或差异说明。当前不能自行选取其中一个金额作为理算基数，也不能据此认定欺诈。

两组都应交付意见单和 JSON，结论一致、来源可追溯。修改规则后重跑两组，既查漏报，也查正常样例是否被新增规则误报。当前样例尚不能证明跨医院、跨患者等场景的泛化效果。

## 4. 关键步骤

### 第一步：先看材料用途和本次要回答的问题（R01）

列出本批次原始文件、类型、页数、可读性和是否有缺页迹象。按材料用途理解信息：病历支持诊疗记录，票据支持收费及支付信息，清单支持费用构成。

**判断要点：** 不要求每个字段在所有材料上重复出现。“只有一个来源”“看不清”“应有内容缺失”“多个来源互相矛盾”分别记录。缺少保单意味着本轮不能核对保险责任，不妨碍继续整理已有就医材料，也不直接生成一份全套理赔补件清单。

### 第二步：先确认材料能否放在一起，再比较内容（R02）

综合医院、院内患者号、就诊号、就诊日期和姓名进行关联。院内编号在对应医院内解释；姓名相同不能单独证明同次就诊。

**判断要点：** 存在明确关联信息且其他信息无冲突时归组；编号等关键信息冲突时不强行合并，保留原材料待人工核实。只有姓名和相近日期、证据不足时标记“关联待核实”。开票日期与就诊日期分别保存，不能混用；日期不同先查业务含义，不直接认定错误。

### 第三步：先核单据内部，再找跨材料差异（R03）

按以下顺序使用代码计算，并保留计算式和来源：

1. 清单有数量、单价时先核行金额，再核明细合计与标示总额；无数量或单价时记录“未提供”，不补造。
2. 核票据费用类别合计与票据总额。
3. 在同次就诊、同币种、同费用范围的前提下，比较票据与清单总额。
4. 对照诊察、检验、药品等类别，定位差额；项目归类不明确时保留待确认映射，不硬凑。
5. 对票据明确列出的支付构成核算，不把重复的小计或“其中项”重复相加。

**判断要点：** 内部加总正确不代表跨材料一致；总额一致也不代表类别都一致。当前教学样例精确到分比较，不设“差得少就自动忽略”的容差；扩展到存在舍入规则的材料时，需先明确适用规则。

### 第四步：保留医学表述和金额口径（R04）

“初步诊断”不改写为确诊，“自述无特殊病史”不改写为已经证实没有既往病史；相对时间保留原文，不把“2天前”直接确定为保险事故发生日。

医疗总费用、医保基金支付、个人支付分别表达。个人支付不能直接充当商业保险赔款，也不能在无依据时拆成医保范围内自付与范围外自费。

**判断要点：** 只写“口服药品组合”时，可以核金额，不能推断具体药名、保障范围或用药合理性。

### 第五步：发现问题后，先定位和核实，再提补件（R05）

对每个问题先回看原件，排除识别或归组错误；再核对现有材料的收费范围、版本和更正记录。已有证据能够解决的，先利用已有证据。

**判断要点：** 补件建议必须说明要解决哪个问题。金额冲突可以建议核对收费记录和对应版本；检查结果未附，只有实际审核问题需要该证据时，才建议补充对应报告。不要因为“初步诊断”自动要求最终诊断，也不要笼统索取全部病史。

核实记录或补充材料暂时不可取得时，写明证据缺口和对当前判断的影响，交人工决定下一步，不自行定案。

### 第六步：按问题对后续处理的影响排顺序（R06）

优先列出妨碍本轮关联或费用核对的问题，其次列出后续特定审核问题需要的证据，再列记录说明。每条写清具体核实动作和建议承接岗位；实际岗位未明确时写“待指定”，不编造客户流程。

**判断要点：**“当前有费用冲突”“后续如核药品范围需具体明细”“本轮未评估保险责任”分别表达，不能全部混成必须向客户补件的异常。

### 第七步：检查意见单与结构化结果，再交人工（R07）

检查数值、计算式、材料来源、规则编号和两种输出的结论是否一致；确认每项建议能对应具体问题、没有超出证据作出判断。生成核实或补件话术只作为草稿，不自动发送。

## 5. 人工确认点

| 何时 | 谁确认 | 看什么、按什么标准决定 | 后续处理 |
| --- | --- | --- | --- |
| 课堂首次使用、规则变更后 | 讲师；用于实际业务前由客户指定理赔专家审核 | 规则是否适用，例外是否充分，输出与样例是否符合本卡要求 | 通过后用于对应范围；有争议则保留待确认并修订、回归验证 |
| 发现关联冲突、金额冲突或关键内容不可读时 | 材料预审人员；课堂由讲师承担 | 原始材料、来源定位、计算及补充证据是否足以解决问题 | 确认后更新结果并留记录；未解决则保持待核实 |
| 拟正式提出补件要求或进入后续审核前 | 客户指定的理赔人员；课堂由讲师承担 | 建议是否必要、是否已有替代证据，表述是否准确，是否超出任务范围 | 人工决定是否采用建议及如何流转；退回时说明修改原因 |

没有收到人工确认时保持“待确认”，不因等待或超时自动通过。实际承接岗位、处理时限和升级路径由客户确定；课堂不虚构这些配置。保险责任与赔款决定由后续获授权人员按适用依据处理。

## 6. 异常情况

| 遇到的情况 | 处理方式 |
| --- | --- |
| 照片模糊、文件打不开、缺页或关键字段无法辨认 | 标记到具体文件和内容；可继续处理其余材料，受影响的检查写“无法核对”；建议重传对应页面，不猜值 |
| 同名但就诊信息不足，或编号等关联信息冲突 | 保留未关联材料，转人工核实；不跨组加总、不强行比较 |
| 重复扫描或相同材料的不同版本 | 标记重复候选及依据；无法确认有效版本时均保留，不重复计费、不删除或自行取最新版本 |
| 金额冲突、费用范围不同或项目无法归类 | 分别保留原始值，注明可比较范围与未完成检查；先核对应关系，再提出具体核实建议，不擅自取较低值、较高值或平均值 |
| 未提供保单、条款或具体药品信息，却被要求判断是否赔付或用药是否合理 | 完成可以完成的预审，说明该判断所缺依据和需人工承接的问题；不调用通用知识补造适用规则 |
| 没有发现本轮范围内的问题 | 明确已检查事项和未检查事项，不为了产出异常而强行补件，也不写成整笔理赔审核通过 |
| 计算或处理工具失败 | 列出未完成项目并标记处理未完成，保存可用结果；不将未执行的检查写成通过 |
