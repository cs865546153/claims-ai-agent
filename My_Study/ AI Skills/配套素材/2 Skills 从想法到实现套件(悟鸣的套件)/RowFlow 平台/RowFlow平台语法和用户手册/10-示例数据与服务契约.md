# 示例数据与服务契约

适用版本：RowFlow 演示规范 1.0。本文是业务示例字段、请求及响应的统一来源。所有姓名、标识、服务和接入引用均为虚构演示数据。

`demo.rowflow.example` 是本资料使用的占位域名，不代表已部署服务。要执行 HTTP/RPC 示例，需要实现对应 mock 或替换为真实的已授权接口；本文只定义契约。

## 1. 业务问题

读取租户 T001 的订单，筛选已支付订单，补充用户所在城市，并按城市统计订单数和金额。没有用户资料的订单可归入“未知”，是否允许把调用失败也降级为未知，必须由具体需求声明。

## 2. 订单字段

| 字段 | 类型 | 示例与规则 |
| --- | --- | --- |
| `orderId` | String | 订单唯一标识，例如 O1001 |
| `tenantId` | String | 租户标识，本组数据均为 T001 |
| `userId` | String | 用户标识；U999 在用户表中不存在 |
| `status` | String | 本例使用 PAID、CREATED |
| `amount` | 十进制字符串 | 金额单位为元，例 `'120.50'`；计算前 decimal |
| `channel` | String | WEB、STORE |
| `createdAt` | String | UTC ISO 8601，统一精度 |

固定订单集，数组顺序即默认输入顺序：

```json
[
  {"orderId":"O1001","tenantId":"T001","userId":"U001","status":"PAID","amount":"120.50","channel":"WEB","createdAt":"2026-10-18T08:00:00Z"},
  {"orderId":"O1002","tenantId":"T001","userId":"U002","status":"CREATED","amount":"80.00","channel":"STORE","createdAt":"2026-10-18T08:10:00Z"},
  {"orderId":"O1003","tenantId":"T001","userId":"U001","status":"PAID","amount":"200.00","channel":"WEB","createdAt":"2026-10-18T08:20:00Z"},
  {"orderId":"O1004","tenantId":"T001","userId":"U003","status":"PAID","amount":"50.00","channel":"STORE","createdAt":"2026-10-18T08:30:00Z"},
  {"orderId":"O1005","tenantId":"T001","userId":"U999","status":"PAID","amount":"100.00","channel":"WEB","createdAt":"2026-10-18T08:40:00Z"}
]
```

## 3. 用户字段

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `userId` | String | 本示例内唯一 |
| `userName` | String | 演示姓名 |
| `city` | String | 城市名称 |
| `level` | String | VIP、NORMAL |

固定用户集：

```json
[
  {"userId":"U001","userName":"林青","city":"杭州","level":"VIP"},
  {"userId":"U002","userName":"陈禾","city":"上海","level":"NORMAL"},
  {"userId":"U003","userName":"周宁","city":"杭州","level":"NORMAL"}
]
```

订单和用户接口均按 tenantId 隔离；示例的 users 响应已经限定为同一租户，因此关联可仅用 userId。跨租户输入必须由明确的复合键或上游过滤保证隔离，不能套用此简化假设。

## 4. HTTP 扫描订单

| 项 | 约定 |
| --- | --- |
| URL | `https://demo.rowflow.example/api/orders` |
| 方法 | GET |
| query | `tenantId`，必填 String，本例 T001 |
| credentialRef | `demo-order-reader` |
| rowsPath | `data.items` |
| 分页 | 不分页；本契约一次返回该租户完整的小型订单列表 |

成功响应为以下结构，其中 `items` 为第 2 节的完整数组：

```json
{
  "data": {
    "items": [
      {"orderId":"O1001","tenantId":"T001","userId":"U001","status":"PAID","amount":"120.50","channel":"WEB","createdAt":"2026-10-18T08:00:00Z"},
      {"orderId":"O1002","tenantId":"T001","userId":"U002","status":"CREATED","amount":"80.00","channel":"STORE","createdAt":"2026-10-18T08:10:00Z"},
      {"orderId":"O1003","tenantId":"T001","userId":"U001","status":"PAID","amount":"200.00","channel":"WEB","createdAt":"2026-10-18T08:20:00Z"},
      {"orderId":"O1004","tenantId":"T001","userId":"U003","status":"PAID","amount":"50.00","channel":"STORE","createdAt":"2026-10-18T08:30:00Z"},
      {"orderId":"O1005","tenantId":"T001","userId":"U999","status":"PAID","amount":"100.00","channel":"WEB","createdAt":"2026-10-18T08:40:00Z"}
    ]
  }
}
```

无订单时为 `{"data":{"items":[]}}`。此接口没有状态、日期范围、page、pageSize 等请求参数；生成示例脚本时应使用本地 filter，不添加契约外参数。

## 5. RPC 扫描用户

| 项 | 约定 |
| --- | --- |
| registryRef | `demo-rpc` |
| service | `demo.user.UserService` |
| method | `listUsers` |
| serviceVersion | `'1.0'` |
| 唯一方法参数 | Map：`[tenantId: 'T001']` |
| rowsPath | `data.users` |
| 幂等属性 | 平台目录标记为幂等查询 |

返回值：

```json
{
  "data": {
    "users": [
      {"userId":"U001","userName":"林青","city":"杭州","level":"VIP"},
      {"userId":"U002","userName":"陈禾","city":"上海","level":"NORMAL"},
      {"userId":"U003","userName":"周宁","city":"杭州","level":"NORMAL"}
    ]
  }
}
```

## 6. RPC 逐行查询用户

| 项 | 约定 |
| --- | --- |
| registryRef / service / serviceVersion | 与第 5 节相同 |
| method | `getUser` |
| 唯一方法参数 | Map：`[tenantId: 'T001', userId: 'U001']` |
| recordPath | `data` |
| 幂等属性 | 平台目录标记为幂等查询 |

U001 的成功响应：

```json
{"data":{"userId":"U001","userName":"林青","city":"杭州","level":"VIP"}}
```

U003 返回第 3 节中对应的用户对象。U999 不存在时返回：

```json
{"data":null}
```

正常未查到必须保留 `data` 字段；返回 `{}` 会被视为缺失路径，而不是正常未命中。

## 7. HTTP 逐行查询用户

| 项 | 约定 |
| --- | --- |
| URL | `https://demo.rowflow.example/api/user` |
| 方法 | GET |
| query | `tenantId`、`userId`，均为必填 String |
| credentialRef | `demo-user-reader` |
| recordPath | `data` |
| 成功/未查到响应 | 与第 6 节相同 |

这个接口可替换 RPC getUser，lookup 的业务闭包不需要改变。配置字段须按 HTTP 源重写，不能混用 registryRef/service 等 RPC 字段。

## 8. 固定验收结果

| 检查项 | 结果 |
| --- | --- |
| 全部订单数 | 5 |
| PAID 订单数 | 4 |
| PAID 金额合计 | 470.50 |
| PAID 且金额至少 100 | O1001、O1003、O1005，共 3 条，合计 420.50 |
| 全部 PAID 左关联后，杭州订单数与金额 | 3 条，370.50，平均 123.50 |
| 全部 PAID 左关联后，未知城市订单数与金额 | 1 条，100.00，平均 100.00 |
| PAID 使用 inner join 的订单数与金额 | 3 条，370.50 |
| 对全部 PAID 用 memory + RPC lookup，无重试 | 4 次远程请求，1 行正常未命中，0 行错误降级 |
| HTTP 订单 scan + RPC 用户 scan，无重试 | 2 次远程请求 |

金额比较按数值而非 JSON 显示的小数位数验收。以上结果来自固定样例的计算，未执行真实网络调用。
