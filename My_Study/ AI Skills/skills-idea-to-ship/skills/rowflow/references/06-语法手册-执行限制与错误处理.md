# 语法手册：执行限制与错误处理

适用版本：RowFlow 演示规范 1.0。本文统一定义默认限制、重试条件、错误码和结果提交行为。

## 1. 执行模型

任务是有界批处理。声明数据源和组装流时不访问业务远程服务；主体结束后才执行 `emit` 指向的处理链。权限和引用可以在执行前校验，远程响应字段类型只能在读取时验证。

- `filter/map/flatMap/select/withFields/skip/limit` 可逐行处理。
- `distinct` 需保留已见键；`sorted` 需保存并排序全部输入。
- `join` 先完整加载右流并建立索引，再消费左流。
- `groupBy/aggregate` 完整消费上游后输出，按键维护聚合状态。
- `lookup` 串行处理，保持输入顺序。

平台不自动并行、下推过滤、重排操作符或缓存数据源。对外最终结果按处理链产生的顺序组成 JSON 数组。

## 2. 任务限制

| pipeline 配置 | 默认值 | 合法范围 | 计量规则 |
| --- | --- | --- | --- |
| `timeoutMs` | 10000 | 整数 `1..60000` | 从任务开始执行处理链，到结果准备完成的总时限；不含排队与编译 |
| `maxRows` | 10000 | 整数 `1..100000` | 每个源读取节点及每个操作符节点累计产生的行数上限 |
| `maxOutputRows` | 1000 | 整数 `1..10000`，且不大于 maxRows | emit 实际接收到的行数上限 |
| `maxLookupCalls` | 1000 | 整数 `1..10000` | 全任务 lookup 实际请求次数，包含每次重试 |

这些是上限，不是自动截断参数。超过上限报 `RF-LIMIT-001` 并使整个任务失败。需要取前 N 条时应明确写 `limit(N)`；仍须考虑前置阻塞操作对输入的完整读取。

按实际拉取并产生的行计数；若 `limit` 提前停止取行，未产生的行不计入节点行数。但 HTTP/RPC `scan` 仍可能已获取完整响应，且始终受响应大小限制约束。

每个远程响应解压后的载荷上限固定为 2 MiB，超过同样报 `RF-LIMIT-001`。此限制由平台接入层执行，1.0 未开放脚本覆盖。行数限制不能精确等价为内存限制；本规范也未定义磁盘溢写。

## 3. 超时与重试

数据源 `timeoutMs` 是一次尝试的上限，包含连接、发送和读取；实际可用时间还受任务剩余时限约束。任务整体超时报 `RF-EXEC-001`，不是某个 lookup 可以降级的源超时。

`retries: 1` 表示最多调用 2 次。首次失败后等待 100ms，第二次失败后如还有重试额度等待 200ms。每次调用与等待均占任务总时限。只对以下失败重试：

| 来源 | 可重试情况 |
| --- | --- |
| HTTP | 网络瞬断、单次调用超时、状态码 429/502/503/504 |
| RPC | 传输不可用、单次调用超时，由适配器分类 |

HTTP 500、其他业务状态码、业务异常、响应解析/路径错误、权限错误、配置错误、脚本错误均不重试。剩余任务预算不足时终止，不能超出总时限继续尝试。

只有幂等调用才允许 `retries > 0`。GET 按幂等处理；POST 与 RPC 须显式配置 `idempotent: true`，且接入目录中的方法也必须被平台标记为幂等。脚本声明不能覆盖目录中的非幂等属性，违背时报 `RF-CONFIG-002`。

平台不对整个脚本自动重跑，不提供跨数据源事务或 exactly-once 保证。1.0 的接入用途为查询；写入型业务接口不在本规范内。

## 4. 错误码

| 错误码 | 含义 | 排查入口 |
| --- | --- | --- |
| `RF-DSL-001` | 解析失败、未知 DSL 方法、未知配置键或被禁用语法 | 检查方法名、括号、版本与白名单 |
| `RF-DSL-002` | 数据源未定义或 scan/lookup 模式不匹配 | 检查名称、声明顺序与 mode |
| `RF-DSL-003` | emit 数量不为一、同一流节点有多个消费者 | 检查终结入口与分支复用 |
| `RF-CONFIG-001` | 配置缺失、类型/枚举/范围不合法、别名冲突 | 对照对应接口参数表 |
| `RF-CONFIG-002` | 非幂等接口启用了重试 | 检查目录属性和 idempotent |
| `RF-PARAM-001` | 必填参数缺失或为 null | 检查提交参数和 param 调用 |
| `RF-PERM-001` | 凭据、服务、方法或域名未授权 | 检查项目接入配置 |
| `RF-SRC-001` | 某次源调用超时，最终未恢复 | 检查源时限、远程延迟及重试 |
| `RF-SRC-002` | 源调用失败，例如 HTTP 错误状态、RPC 业务/传输异常 | 检查响应状态与适配器错误类别 |
| `RF-SRC-003` | 响应解析失败、路径缺失或响应目标类型错误 | 检查 rowsPath/recordPath 和服务契约 |
| `RF-TYPE-001` | 字段转换失败、键类型或闭包返回类型错误 | 检查字段类型和闭包返回值 |
| `RF-ROW-001` | 修改了只读 Row 或其嵌套容器 | 用 map/withFields 构造新行 |
| `RF-LIMIT-001` | 行数、输出数、lookup 请求数或响应大小超限 | 缩小数据范围或减少展开/关联 |
| `RF-EXEC-001` | 任务总时限耗尽 | 检查整个调用链及串行 lookup |
| `RF-EXEC-002` | 其他闭包执行异常，如除零 | 检查错误定位的操作符与表达式 |

代码首先按最具体的错误类别分类。平台返回的 `details` 可以包含 HTTP 状态或适配器错误类别；它不是可在脚本中捕获的新异常类型。

## 5. lookup 的局部降级

`lookup(..., [onError: 'null', ...])` 仅允许把最终的 `RF-SRC-001`、`RF-SRC-002` 转为空结果。是否可以重试，仍然按上一节的更细条件判断；不可重试的 `RF-SRC-002` 可以直接进入该显式降级。

`RF-PERM-001`、`RF-SRC-003`、配置/字段/闭包错误、请求构造错误、`RF-LIMIT-001`、`RF-EXEC-001` 一律不降级。正常未查到与调用失败降级分别计数，不能把“未知城市”当作“用户一定不存在”。

`from`、`join` 和 `union` 的扫描输入没有 `onError` 选项，也不会在服务不可用时返回空表。`filter` 无法处理尚未成功读取的数据源错误。

## 6. 输出原子性

运行期间先缓冲最终结果，处理链全部成功才提交 JSON 数组。失败时没有可用的部分业务结果，已经发生的远程调用不会撤销。预览同样执行真实读取；仅静态校验不访问业务远程服务。

成功任务的业务结果为数组，不包含内部元数据。平台任务详情另外保存元数据，例如：

```json
{
  "runId": "run_demo_001",
  "status": "SUCCEEDED",
  "pipeline": "city_sales",
  "outputRows": 2,
  "sourceRequests": 2,
  "lookupMissRows": 0,
  "lookupErrorFallbackRows": 0,
  "elapsedMs": 42
}
```

`sourceRequests` 为所有远程实际尝试次数，包含 scan、lookup 和重试，不包含 memory 读取。`lookupMissRows` 仅统计成功响应为 `null` 的输入行；`lookupErrorFallbackRows` 仅统计显式降级的输入行。

失败详情格式示例：

```json
{
  "runId": "run_demo_002",
  "status": "FAILED",
  "code": "RF-SRC-003",
  "source": "orders",
  "operator": "from",
  "message": "rowsPath data.items must resolve to an array",
  "details": {"path": "data.items", "actualType": "null"}
}
```

错误信息使用源名称、节点位置与经过脱敏的上下文定位问题，不包含认证信息或完整业务响应。
