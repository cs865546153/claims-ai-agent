# 语法手册：数据源配置

适用版本：RowFlow 演示规范 1.0。本文是 `source` 配置的权威定义。接入权限见 [平台接入知识](08-平台知识-接入权限与性能.md)，示例响应见 [服务契约](10-示例数据与服务契约.md)。

## 1. 注册与读取方式

```groovy
source('orders', [type: 'memory', rows: [[orderId: 'O1001']]])
def orders = from('orders')
```

数据源名称在任务内唯一，使用 `[a-z][a-zA-Z0-9_]{0,63}`，不等同于服务端接口名。配置在声明阶段求值，注册后只读。

| `mode` | 输入方式 | 返回形态 | 使用位置 |
| --- | --- | --- | --- |
| `'scan'`，默认 | 注册时的静态参数 | 记录数组，每条转为一个 `Row` | `from('name')` |
| `'lookup'` | 静态参数加当前行产生的动态参数 | 单个对象或 `null` | `stream.lookup('name', ...)` |

`memory` 仅支持 `scan`。`http` 和 `rpc` 支持两种模式。`scan` 每次独立读取只请求一次，不提供自动分页、游标循环或持续订阅。

## 2. 通用配置

| 字段 | 类型 | 默认值与约束 |
| --- | --- | --- |
| `type` | String | 必填；`memory`、`http`、`rpc` |
| `mode` | String | 默认 `'scan'` |
| `timeoutMs` | Integer | 远程源默认 `1000`；范围 `1..10000`，每次尝试的总耗时上限 |
| `retries` | Integer | 远程源默认 `0`；范围 `0..2`，表示初次调用之后的追加尝试次数 |
| `idempotent` | Boolean | HTTP GET 固定按幂等处理；HTTP POST 与 RPC 默认 `false` |
| `rowsPath` | String | 远程 `scan` 必填；结果数组路径 |
| `recordPath` | String | 远程 `lookup` 必填；单个结果对象路径 |

通用表的远程配置不适用于 `memory`。`rowsPath` 与 `recordPath` 根据模式二选一，多配、漏配均报配置错误。重试规则和重试预算见 [执行与错误处理](06-语法手册-执行限制与错误处理.md)。

HTTP GET 的 `idempotent` 可以省略或显式设为 `true`，设为 `false` 报 `RF-CONFIG-001`。POST 和 RPC 使用默认值或显式 Boolean；开启重试时还须通过平台目录的幂等校验。

## 3. 内存数据源

```groovy
source('orders', [
    type: 'memory',
    rows: [
        [orderId: 'O1001', userId: 'U001', amount: 120.50G],
        [orderId: 'O1002', userId: 'U002', amount: 80.00G]
    ]
])
```

`rows` 必填，类型为 `List<Map>`，允许空列表。声明阶段复制数据，每次读取保持列表顺序。列表中的 `null`、标量或嵌套列表不能作为一条记录。字段内可以包含嵌套 Map/List。

内存数据源适合最小演示、规则表及小型固定维表。它没有网络访问，也不能设置认证、超时或重试。

## 4. HTTP 数据源

```groovy
source('orders', [
    type: 'http',
    mode: 'scan',
    method: 'GET',
    url: 'https://demo.rowflow.example/api/orders',
    query: [tenantId: param('tenantId', 'T001')],
    headers: [Accept: 'application/json'],
    credentialRef: 'demo-order-reader',
    rowsPath: 'data.items',
    timeoutMs: 1200,
    retries: 1
])
```

| HTTP 专有字段 | 类型 | 规则 |
| --- | --- | --- |
| `method` | String | 必填；只支持 `'GET'`、`'POST'` |
| `url` | String | 必填；固定 HTTPS 地址，域名须在平台白名单内 |
| `query` | Map | 默认 `[:]`；查询参数，由适配器进行 URL 编码 |
| `headers` | Map<String,String> | 默认 `[:]`；普通业务请求头 |
| `body` | Map | POST 可用，默认 `[:]`；序列化为 JSON；GET 不接受此字段 |
| `credentialRef` | String | 可省略；引用当前项目已授权的凭据 |

1. HTTP `2xx` 进入 JSON 解析；`204` 由于没有 JSON 响应体，报响应结构错误。
2. `3xx` 不自动跟随；`4xx/5xx` 按调用失败处理。可重试状态码见错误处理文档。
3. HTTP 成功状态不代表业务成功。1.0 没有 `successExpression` 或业务码映射配置；若上游需要专有业务码检查，应先通过平台接入适配层提供符合本规范的接口。
4. `Authorization`、`Cookie`、`Host` 等受保护请求头由平台管理，脚本不能设置；凭据不作为普通运行参数传入。
5. 固定 URL 及路径写在配置中，业务值通过 `query` 或 `body` 传递。1.0 不支持逐行替换 URL。

HTTP `lookup` 示例：

```groovy
source('userByIdHttp', [
    type: 'http',
    mode: 'lookup',
    method: 'GET',
    url: 'https://demo.rowflow.example/api/user',
    query: [tenantId: 'T001'],
    credentialRef: 'demo-user-reader',
    recordPath: 'data'
])
```

`lookup` 的动态请求 Map：GET 时覆盖合并到 `query`，POST 时覆盖合并到 `body`；同名键以动态值为准，其他静态键保留。POST 的 `query` 保持注册值。动态 Map 不能改写 URL、请求头或认证。写法见 [多源组合](05-语法手册-多源组合与聚合.md)。

## 5. RPC 数据源

```groovy
source('users', [
    type: 'rpc',
    mode: 'scan',
    registryRef: 'demo-rpc',
    service: 'demo.user.UserService',
    method: 'listUsers',
    serviceVersion: '1.0',
    args: [tenantId: 'T001'],
    rowsPath: 'data.users',
    timeoutMs: 800,
    retries: 1,
    idempotent: true
])
```

| RPC 专有字段 | 类型 | 规则 |
| --- | --- | --- |
| `registryRef` | String | 必填；项目内已授权的 RPC 接入配置 |
| `service` | String | 必填；服务接口全名，须与服务目录一致 |
| `method` | String | 必填；方法名，须与授权方法一致 |
| `serviceVersion` | String | 默认 `'1.0'`；是业务服务版本，不是 DSL 版本 |
| `args` | Map | 默认 `[:]`；作为 RPC 方法唯一的 Map 参数 |

本规范假设平台 RPC 适配器暴露 `Map -> Map/List` 的方法契约，不包含 Java 重载选择、多位置参数、IDL 编译或业务 DTO 构造。实际 RPC 协议由 `registryRef` 绑定的接入配置决定，脚本不设置注册中心密码或地址。

RPC `lookup` 使用 `recordPath`；动态请求 Map 覆盖合并到静态 `args`。RPC 的服务名、方法名和版本固定，不能根据当前行切换。

## 6. 响应路径

路径是本框架的简化字段路径，不是 JSONPath：

| 路径 | 含义 |
| --- | --- |
| `'$'` | 整个响应根值 |
| `'data.items'` | 根对象的 `data` 字段下的 `items` 字段 |
| `'data'` | 根对象的 `data` 字段 |

不支持 `$.data.items`、数组下标、通配符、表达式、包含点号的字段名。路径中间层必须是对象，且路径必须存在。

`scan` 的目标必须为数组，元素必须为对象；空数组产生零行，`null` 和缺失路径均报 `RF-SRC-003`。`lookup` 的目标必须为对象或显式 `null`；`null` 表示没有匹配，缺失路径、数组、标量均报 `RF-SRC-003`。根路径 `'$'` 也遵循相同类型规则。

## 7. 请求和字段转换

接入层把 JSON 对象或 RPC 返回对象转为 Map，再包装为 Row。不会自动展开 `data`、展开数组、转驼峰、把数值字符串变为数字，或根据名字推断时间类型。

静态请求值和 `lookup` 返回的动态请求值都应是 JSON 可表达的 Map/List/标量。动态请求必须返回 Map；不支持通过返回 `null` 跳过调用，需要先用 `filter` 筛选可调用的行。

## 8. 明确的能力边界

1.0 不定义 JDBC、Kafka、文件、GraphQL、WebSocket、自定义分页、批量 lookup 或缓存配置。新增数据源类型需要先扩展规范与适配器，再生成对应脚本，不能只在脚本里写一个新 `type`。
