# 本地部署架构

```mermaid
flowchart LR
    subgraph client["调用方"]
        browser["客服与审核终端"]
    end
    subgraph service["理赔服务（单进程）"]
        api["FastAPI + 接入层中间件<br/>RequestID / 认证 / 限流 / 审计"]
        orch["LangGraph 编排"]
        llm["本地或云端 OpenAI 兼容推理"]
        consumer["已授权业务消费者"]
    end
    subgraph datastore["数据存储"]
        checkpoints["SQLite 审核检查点"]
        audit["SQLite 审计库<br/>只追加 + 哈希链"]
        memory["Redis 会话"]
        vectors["Milvus 条款库"]
        outbox["持久化 Outbox"]
    end
    subgraph external["适配及观测"]
        legacy["组织内核心系统适配器"]
        trace["自托管 LangFuse"]
        metrics["Prometheus /metrics"]
    end
    browser -->|"8001 HTTP / SSE"| api
    api --> orch
    orch -->|"模型调用"| llm
    api -->|"审计落库（响应结束后）"| audit
    orch -->|"保存及恢复"| checkpoints
    orch -.->|"可选：会话持久化"| memory
    orch -.->|"可选：检索条款"| vectors
    orch -.->|"规划：审批后入队"| outbox
    consumer -->|"取出待投递事件"| outbox
    consumer -.->|"核心系统：幂等投递"| legacy
    orch -.->|"核心系统：核实证据"| legacy
    api -.->|"脱敏追踪"| trace
    api -->|"指标暴露"| metrics
```

会话和检索为可选注入；Outbox 组件已实现但主图未接入。真实接口须配置后启用。当前 HTTP 示例为单工作进程；不要直接据此增加副本。

- `/health` 只表示进程存活，`/ready` 额外检查理赔图与审计库。
- 接入层限流桶、模型层 TTL 缓存都在进程内；多副本部署前需换 Redis。
- 审计链校验：`python -m scripts.audit_verify --limit 10`（退出码 0 = 完整）。
