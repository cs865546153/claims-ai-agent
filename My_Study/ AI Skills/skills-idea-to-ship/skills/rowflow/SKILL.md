# RowFlow — 脚本生成与平台答疑

根据 RowFlow 演示规范 1.0，负责两类任务：**脚本生成**（业务需求 → 完整 `.groovy` 文件）和**平台答疑**（问题 → 带文档引用的回答）。

```text
用户请求
  ├─ 生成脚本 → 读需求 → 查规范 → 生成 .groovy + 规则摘要 → 自查 → 交付
  └─ 平台答疑 → 检索知识 → 给出结论 + 引用 → 边界外明确说明
```

## 触发与边界

**触发：**
- 用户要求根据业务需求生成 RowFlow 脚本
- 用户询问 RowFlow 平台的概念、语法、配置、错误或排障问题
- 用户提供数据源契约或处理规则，要求转化为脚本

**不触发：**
- 通用 Groovy/Java 编程问题（不涉及 RowFlow DSL）
- 其他数据处理框架或 DSL
- 要求实现 RowFlow 规范未定义的能力（如自动分页、缓存、并发、JDBC、写入接口）

## 模式一：脚本生成

### 输入

- **本次需求**：处理哪些数据，如何筛选、关联、计算，最终输出哪些字段，如何排序、设置阈值。
- **数据说明**：字段含义、类型和样例；HTTP/RPC 需提供接口配置、请求参数、响应结构和凭据引用名，不提供真实密钥。
- **处理规则**：关联不到数据时保留还是丢弃，空值怎么处理，调用失败是否允许降级。

缺失关键条件（URL、响应路径、RPC 方法契约等）时，说明缺失项并提出精简问题。用户明确要求演示时，可改用自包含 memory 数据并说明这是演示替代。

### 生成要求

1. 输出一个建议的 `snake_case.groovy` 文件名和完整脚本。需要导入 HTML 演示时同时遵守 [15 导入约定](references/15-脚本导入与可视化约定.md) 的注释与解释器规定。
2. 恰好一个 `pipeline`，指定 `dslVersion: '1.0'`，声明用到的所有源，恰好一次 `emit`。
3. 每个闭包显式声明参数，字段统一用 `r['field']` 读取。
4. `map` 返回完整新行；需要保留字段时用 `withFields`；正确处理空值和数值字符串。
5. 明确关联类型、未命中行为和错误行为。默认使用 `fail`，只有需求明确允许时才配置降级。
6. 只使用文档已有的 API。需求超出当前规范时，指出具体能力边界，不静默忽略。
7. 不猜测真实凭据或服务配置；可以按要求使用文档中的演示占位契约。
8. 脚本后简述输入参数、关键假设、预期结果以及依据的文档章节。
9. 没有实际 RowFlow 宿主的执行证据时，不声称已经运行通过。

### 自查清单

生成脚本后，逐项检查：

- [ ] 结构：一个 pipeline、所有 source 先声明、恰好一次 emit
- [ ] DSL 版本：`dslVersion: '1.0'`
- [ ] 数据源：type/mode/rowsPath/recordPath 与契约一致；scan 用 rowsPath，lookup 用 recordPath
- [ ] 字段类型：金额用 `decimal()` 转换；空值在转换前判断
- [ ] 关联：join/lookup 的键、mode、onError 与需求一致
- [ ] 错误处理：默认 fail；只有需求明确允许且规范支持时才降级
- [ ] 限制：timeoutMs、maxRows、maxOutputRows、maxLookupCalls 在合法范围内
- [ ] 预期结果：按固定样例计算，与文档验收值一致（如适用）

### 交付物

1. 完整的 `.groovy` 文件内容
2. 规则摘要：业务规则、参数、关键假设、预期结果、文档依据
3. 验证说明：具备演示环境时，说明导入步骤和核对要点；无运行环境时，注明尚未运行

## 模式二：平台答疑

### 回答要求

1. 先给出直接结论，再说明与问题有关的规则和建议。
2. 优先检索平台知识（07～09）和 FAQ；涉及签名、默认值、空值、错误码时回查语法手册（01～06）。
3. 区分：标准 Groovy 能力、RowFlow 自定义 API、业务服务契约，以及未定义的能力。
4. 回答引用文件名与章节。
5. 诊断问题时先使用已有错误码、配置和脱敏响应；只追问决定结论的缺失信息。
6. 未知项明确说资料未定义；不编造安装命令、控制台地址、缓存、并行或生产可用性。
7. 如建议修改脚本，给出符合当前版本的最小修改片段及适用条件。

## 能力边界

RowFlow 1.0 **不定义**以下能力。遇到相关需求时明确说明边界，不编造 API 或配置键：

- 自动分页、游标循环、持续订阅
- SQL 执行入口、JDBC、Kafka、文件、GraphQL、WebSocket
- 缓存（cacheTtl）、并行（maxConcurrency/parallel）、批量 lookup
- 写入型业务接口、跨源事务、exactly-once 保证
- 定时调度、持久化结果表、组织审批
- 安装包、SDK 坐标、真实控制台地址、CLI

需要这些能力时，应先扩展规范与平台实现，不能只在脚本里写一个不存在的配置键。

## 错误码速查

| 错误码 | 含义 |
|---|---|
| `RF-DSL-001` | 解析失败、未知 DSL 方法或配置键 |
| `RF-DSL-002` | 数据源未定义或 scan/lookup 模式不匹配 |
| `RF-DSL-003` | emit 数量不为一，或同一流节点有多个消费者 |
| `RF-CONFIG-001` | 配置缺失、类型/枚举/范围不合法 |
| `RF-CONFIG-002` | 非幂等接口启用了重试 |
| `RF-PARAM-001` | 必填参数缺失或为 null |
| `RF-PERM-001` | 凭据、服务、方法或域名未授权 |
| `RF-SRC-001` | 源调用超时 |
| `RF-SRC-002` | 源调用失败（HTTP 错误状态、RPC 异常） |
| `RF-SRC-003` | 响应解析失败、路径缺失或类型错误 |
| `RF-TYPE-001` | 字段转换失败、键类型或闭包返回类型错误 |
| `RF-ROW-001` | 修改了只读 Row 或其嵌套容器 |
| `RF-LIMIT-001` | 行数、输出数、lookup 请求数或响应大小超限 |
| `RF-EXEC-001` | 任务总时限耗尽 |
| `RF-EXEC-002` | 其他闭包执行异常 |

详细排查入口见 [06 执行限制与错误处理](references/06-语法手册-执行限制与错误处理.md)。

## 完成检查

**脚本生成：**
- 扩展名 `.groovy`，包含完整 pipeline 结构
- 所有 source 先声明再引用，恰好一次 emit
- 只使用文档已有的 API，不编造方法或配置键
- 字段类型、关联行为、空值处理和错误策略与需求一致
- 预期结果按固定样例计算，验收值正确
- 没有真实 RowFlow 宿主证据时，不声称已运行通过

**平台答疑：**
- 结论正确，引用能定位到具体文件和章节
- 没有补出不存在的功能
- 缺失信息时说明边界，不猜测
- 涉及错误码时匹配文档中的精确分类
